# AL-thmany 4.0 Stability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a stability-focused AL-thmany 4.0 source package that prevents Sender/Extractor UI races, hardens group discovery, adds focused pure regressions, and improves reproducible verification.

**Architecture:** Keep the single Android application and both existing runtime families. Extend the existing Extractor operation coordinator into the shared process-local ownership authority, then make Sender participate in that authority while retaining persistent Sender state for recovery. Move group-title filtering into a pure Kotlin policy so false-positive UI labels can be regression-tested without Android.

**Tech Stack:** Kotlin, Android AccessibilityService, Android SDK 36, Kotlin coroutines, SQLite, Jetpack Compose/ViewBinding, Shizuku, Bash/Python validation scripts.

**Spec:** `docs/superpowers/specs/2026-09-16-al-thmany-4.0-stability-design.md`

## Global Constraints

- Preserve existing Sender, extraction, scan, publish, Shizuku, profile, export, and checkpoint features.
- Never allow two active AL-thmany engines to control WhatsApp UI concurrently.
- Do not bypass WhatsApp restrictions, rate limits, or permission boundaries.
- Keep Android minimum SDK 26 and compile/target SDK 36.
- Keep Java/Kotlin JVM target 17.
- Do not cache `AccessibilityNodeInfo` beyond the current UI decision.
- Treat a full Android build as verified only if actually executed successfully.

fun ensureOwned(operation: RuntimeOperation): Boolean {
